# 원격 연결 상태

CLAUDE.md의 File Operations 절에서 나눈 규칙이다.

- 원격 연결 상태: `RemoteConnectionRepository.connectionState`(sealed `RemoteConnectionState`: `Disconnected` / `Connected(serverName)` / `Lost`). 연결된 상태는 연결한 서버 이름을 함께 담는다(연결 여부와 서버가 어긋나지 않도록 한 값). 연결 상태는 탐색 세션(목록 조회·이름 변경·새 폴더가 쓰는 세션, `FtpSessionManager`)만 나타낸다 — 진행 표시가 있는 원격 작업의 작업 세션(`.claude/rules/ftp.md`의 세션 단위)이 끊기거나 서버가 거부해도 상태·끊김 알림에 나오지 않고 그 작업의 실패로만 알린다(#436). 예기치 않은 끊김(연결된 탐색 세션에서만 — 세션이 끊김을 알리면(`FtpSession`의 `onLost`) 관리자가 그 세션이 아직 연결된 탐색 세션인지 보고 정한다)은 사건이 아니라 `Lost` 상태로 다음 연결 시도(`FtpSessionManager.connect`)나 종료 요청까지 남는다 — 끊긴 뒤에 관찰을 시작한 쪽도 알 수 있도록. 앱이 요청한 종료·서버 전환은 `Disconnected`다. 연결 시도(`FtpSessionManager.connect`)는 시작할 때 이전 탐색 세션이 연결돼 있었어도 `Disconnected`로 두고 새 세션 객체로 접속한다 — 이전 세션은 더 이상 탐색 세션이 아니므로 그 명령이 실패해도 `Lost`가 되지 않는다. 끊김 처리는 화면 수명과 무관하게 각자 상태를 보고 한다: `FileTransferCoordinatorViewModel`은 끊긴 세션에 기대는 전송 상태(다운로드 대기, 원격 선택·업로드 대기)를 버리고, 원격 화면은 연결된 세션이 없으면(`Lost`·`Disconnected`, 들어올 때 이미 없어도) 자기 화면만 닫는다(루트 뒤로가기와 같은 결과, #492) — 아래에 로컬 목록이 쌓여 있으면 로컬 목록과 로컬 선택이 남고, 혼자 있었으면 그래프가 함께 꺼져 저장소 선택으로 간다. 저장소까지 거슬러 나가면 쌓여 있던 로컬 상태까지 사라지므로. 끊김 알림은 연결된 상태를 `Lost`로 바꾸는 곳(`FtpSessionManager`)이 같은 잠금 안에서 알림함(꺼내는 쪽 `ConnectionLossNoticeRepository`, 넣는 쪽 `ConnectionLossNoticeReporter`(data — 넣는 곳이 원격 구현뿐이므로), 구현 `ConnectionLossNotices`)에 넣고, 화면 호스트가 작업 메시지와 같이 Snackbar로 알린다(#281) — 상태 흐름을 관찰해 넣으면 빠르게 이어진 변화에서 끊김을 건너뛸 수 있으므로. 보이는 화면이 없을 때 끊긴 것은 다시 보일 때 알리고, 알리기 전에 새 연결을 시작하면(`FtpSessionManager.connect`) 빼서 새 연결이 끊긴 것으로 보이지 않게 한다.
- 원격 연결은 사용자가 저장소 화면에서 서버를 고를 때만 시작한다(`RemoteConnectionUseCase.connectAndNavigate`). 화면 생성이 연결을 시작하지 않으며, 자동 재연결은 없다 — 프로세스가 종료되면 연결도 사라지고, 복원된 원격 화면은 세션이 없으므로 닫힌다. 원격 화면으로 가는 진입은 연결된 세션이 있을 때만 한다(`RemoteSessionCheckUseCase`): 로컬 화면의 하단 원격 전환은 세션이 없으면 저장소 화면으로 가고, 업로드 진입은 거부를 알림함(`NoticeMessage.NoRemoteSession`)에 넣고 로컬 선택을 그대로 둔다(저장소 화면으로 가면 그래프가 꺼내져 선택이 사라지므로). 원격 작업 진행 알림은 세션이 없으면 원격 화면으로 가지 않고 진행 다이얼로그만 띄운다(`ProgressDialogViewModel`, #492 — 작업 세션은 탐색 세션과 따로라 탐색 연결 없이도 알림이 남는다).
- 연결 실패는 결과를 받은 화면(저장소 화면)이 이유로 나눠 알린다(`ConnectFailureNotice`): 접속 정보·네트워크를 확인하고 다시 시도할 실패(시간 초과·호스트 없음·접속할 수 없음·로그인 거부·그 밖의 연결 실패, #408 — `FtpSessionManager.unreachableReasonOf`가 접속 예외 타입으로 나눈다. Android는 소켓 연결 실패를 errno와 관계없이 대부분 `ConnectException`으로 던지므로 서버의 거부와 네트워크 문제는 나누지 않는다)는 알림함(넣는 쪽 `ConnectFailureAlertReporter`, 꺼내는 쪽 `ConnectFailureAlertRepository`, 구현 `ConnectFailureAlerts`)에 넣어 화면 호스트가 Snackbar로 알리고(#371 — 실패를 받은 화면이 그사이 사라지거나 보이지 않아도 잃지 않도록), 새 연결 시도를 시작하면 `RemoteConnectionUseCase.connectAndNavigate`가 아직 알리지 않은 실패를 빼며, 서버나 포트를 쓸 수 없는 실패는 그 화면 ViewModel의 다이얼로그 상태로 닫을 때까지 남긴다.
