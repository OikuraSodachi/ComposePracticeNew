# 화면 이동: 연타 막기와 일회성 요청

`CLAUDE.md` Navigation 절의 세부다. 백스택 모양은 `CLAUDE.md`에 있다.

- 연타(여러 번 처리하면 결과가 틀어지는 입력은 처리 중에 다시 받지 않는다 — 전역 `rules/repeated-input.md`)의 이 앱 적용(#535): 사용자 입력으로 화면을 떠나는 `navigate`·`popBackStack`은 실행 직전에 그 destination의 entry를 `isResumed`로 확인한다(압축 파일 내용 보기 이동 #537 포함). 예외로 저장소 화면은 저장소 클릭을 `dropUnlessResumed`로 클릭 시점에 버리고, 연결·경로 설정 뒤의 이동 요청은 화면이 RESUMED가 될 때까지 보관했다가 처리한다(#542) — 연결하는 동안 백그라운드로 가도 돌아오면 넘어가도록. 보관은 그 화면 방문에 묶인다: 다른 화면으로 떠나면(RESUMED를 벗어날 때 백스택 맨 위가 다른 화면이면) 보관한 요청과 진행 중인 열기의 요청을 버리고(열기 작업 자체는 끝까지 진행한다), 저장소를 여는 동안(로컬 경로 설정 포함)에는 목록 입력을 막는다. 화면을 떠나지 않는 비동기 처리(저장소 열기, 압축 파일 내용 보기 안의 고르는 화면 열기)는 entry가 RESUMED로 남아 위 확인으로 막지 못하므로, ViewModel이 `ExclusiveLauncher`로 처리 중에 다시 들어온 입력을 버린다(#551). 화면 전환 애니메이션은 쓰지 않는다(NavHost 전환 None, 뒤로가기 포함) — 기본 crossfade 700ms 동안 입력이 버려지고 화면 이동이 늦게 느껴졌다. 다이얼로그 확인은 `GuardedConfirmButton`이 막는다. 확인하지 않는 이동: 세션 없음으로 원격 화면 닫기(`onNoSession`), 비밀번호 질문 취소로 내용 보기 닫기(`closeRequest`) — 버리면 화면이 상태와 맞지 않게 남는다. 원격 진행 알림 클릭은 화면 밖 입력이라 지금 route로 판정한다. 열 수 없는 항목을 누를 때마다 거부를 알리는 것(#350)은 연타해도 맞는 결과다.
- ViewModel이 화면에 요청하는 일회성 동작(화면 이동·닫기·앱 종료)은 Channel·SharedFlow 이벤트가 아니라 상태로 보관한다(`PendingRequest`, 전역 `rules/compose-ui.md`, #534) — 이벤트는 받는 쪽이 꺼낸 뒤 처리하기 전에 수집이 취소되거나(`LaunchedEffect`의 디스패처는 즉시 실행하지 않는다) 받는 쪽이 없는 동안(회전) 보내면 사라진다. 화면은 `PendingRequestEffect`로 받아 처리한 직후 suspend 없이 처리했다고 알린다. 처리 시점에 버리는 요청(떠나는 중인 화면의 내용 보기 이동, 갈 수 없는 화면의 원격 알림 이동)도 처리한 것으로 알린다 — 보관했다가 나중에 실행하지 않도록.
- 연결된 원격 세션이 없어 원격 화면이 나갈 때도 루트 뒤로가기와 같이 원격 화면만 닫는다(#492) — 나가는 곳은 위 백스택 모양이 정한다.
- 목록 화면 상태 저장·복원: 그래프 안에서 목록 화면을 꺼낼 때(탭 전환·다운로드 진입)는 그 화면의 상태를 저장하고(`saveState`), 목록 화면으로 갈 때(탭 전환·업로드 진입·원격 알림·다운로드 진입)는 저장된 상태를 복원한다(`restoreState`) — 탭을 오갈 때 화면·ViewModel을 새로 만들지 않도록. 백스택 모양은 바뀌지 않는다. 루트 뒤로가기·세션 없음으로 닫는 화면은 저장하지 않는다(떠나는 동작이므로). 저장 상태는 저장소 화면에서 그래프로 들어갈 때 지운다(`enterFileBrowser`) — 지난 방문(이전 연결)의 화면이 복원되지 않도록. 나가는 경로는 여럿이지만 들어오는 곳은 저장소 화면뿐이다. 다이얼로그는 복원되지 않는다(`rememberScreenDialogState`가 화면이 컴포지션을 떠날 때 닫는다). 5초 넘게 떠나 있던 목록을 다시 조회하는 것은 데이터 레이어의 의도된 동작(`FileListFlowProducer`의 `onStopped`)이라 복원과 무관하다.
